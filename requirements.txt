# Runtime dependencies (Python 3.11).
#
# ORDER MATTERS. Install the platform PyTorch wheel FIRST, then this file.
#
# PyTorch is deliberately absent from this list so a resolver never replaces the
# CUDA build with a generic one. But diffusers and transformers both depend on
# torch, so installing this file into an environment with NO torch will silently
# pull a CPU wheel — and on Windows that means the whole application runs on the
# CPU, or fails the stack gate, with nothing obviously wrong in the install log.
#
#   1. pip install torch --index-url https://download.pytorch.org/whl/cu130
#   2. pip install -r requirements.txt
#   3. pip install -r requirements-dev.txt         # pytest is NOT in this file
#   4. python -m pytest -m stack_compatibility     # confirms the floor was met
#
# Step 3 is not optional on a host that runs step 4. This file carries runtime
# dependencies only, so an install that stops at step 2 has no test runner and
# step 4 fails with `No module named pytest`.
#
# Required floor, enforced by the installed libraries rather than by this file:
#   torch >= 2.6   (transformers 5.x refuses to enable PyTorch below 2.5; 2.6 is
#                   where torch.load defaults to weights_only=True, which is the
#                   gate on Wan's .pth pickles — see the stack compatibility test)
#
# Versions below were resolved by T008 against tests/integration/test_stack_compatibility.py.
#
# The video stack loads through DiffSynth, not Diffusers. Neither
# WanSpeechToVideoPipeline nor WanS2VTransformer3DModel exists in any Diffusers
# release (huggingface/diffusers#12257 is still open), so that route would mean
# running a fork of the core library. DiffSynth ships both from a versioned
# package, leaving Diffusers stock.

-r requirements-core.txt

# --- Voice: VOICE role — UNRESOLVED, deliberately not pinned here ---
# The chosen model is ResembleAI/chatterbox (23 languages including Arabic, MIT).
# It CANNOT be installed into this environment: chatterbox-tts 0.1.7 hard-pins
# torch==2.6.0, transformers==5.2.0, diffusers==0.29.0 and gradio==6.8.0. On the
# production host that downgrade removes the cu130 build and sm_120 support, so
# pip would silently disable the RTX 5080 — the exact failure this file's header
# warns about, arriving through a dependency instead of a missing wheel.
#
# Two ways out, neither yet chosen (see research.md, "Voice packaging conflict"):
#   * run Chatterbox in its own virtualenv and invoke it as a subprocess, which
#     also isolates the TTS slot for later swaps;
#   * use XTTS-v2 through coqui-tts, which pins nothing against torch but whose
#     weights are CPML (non-commercial).
# Until that is settled the voice half of the stack gate skips rather than fails.
