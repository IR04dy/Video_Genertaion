# Runtime dependencies (Python 3.11).
#
# ORDER MATTERS. Install the platform PyTorch wheel FIRST, then this file.
#
# PyTorch is deliberately absent from this list so a resolver never replaces the
# CUDA build with a generic one. But diffusers and transformers both depend on
# torch, so installing this file into an environment with NO torch will silently
# pull a CPU wheel — and on Windows that means the whole application runs on the
# CPU, or fails the stack gate, with nothing obviously wrong in the install log.
#
#   1. pip install torch --index-url https://download.pytorch.org/whl/cu130
#   2. pip install -r requirements.txt
#   3. pip install -r requirements-dev.txt         # pytest is NOT in this file
#   4. python -m pytest -m stack_compatibility     # confirms the floor was met
#
# Step 3 is not optional on a host that runs step 4. This file carries runtime
# dependencies only, so an install that stops at step 2 has no test runner and
# step 4 fails with `No module named pytest`.
#
# Required floor, enforced by the installed libraries rather than by this file:
#   torch >= 2.6   (transformers 5.x refuses to enable PyTorch below 2.5; 2.6 is
#                   where torch.load defaults to weights_only=True, which is the
#                   gate on Wan's .pth pickles — see the stack compatibility test)
#
# Versions below were resolved by T008 against tests/integration/test_stack_compatibility.py.
#
# The video stack loads through DiffSynth, not Diffusers. Neither
# WanSpeechToVideoPipeline nor WanS2VTransformer3DModel exists in any Diffusers
# release (huggingface/diffusers#12257 is still open), so that route would mean
# running a fork of the core library. DiffSynth ships both from a versioned
# package, leaving Diffusers stock.

-r requirements-core.txt

diffsynth==2.1.5           # WanVideoPipeline, ModelConfig, wan_video_dit_s2v

# THE TRANSFORMERS CEILING (measured on the RTX 5080 host, 2026-09-01).
# 4.57.1 is a CEILING as much as a pin, and the two halves of the stack pull in
# opposite directions across it:
#   * coqui-tts 0.27.5 cannot run on transformers 5.x at all. XTTS reaches
#     tortoise/autoregressive.py through TTS/tts/layers/xtts/gpt.py, which imports
#     `isin_mps_friendly` from transformers.pytorch_utils -- removed in 5.0. This
#     is on the inference path, so it cannot be avoided by not using Tortoise.
#     coqui-tts declares `transformers>=4.57` with no upper bound, so the resolver
#     will happily install a 5.x that cannot import. The floor is upstream's bug;
#     this ceiling is the fix.
#   * diffsynth 2.1.5 declares transformers with no bound at all. Its 5.x-only
#     imports (Qwen3_5, Qwen3VL, Ministral3, DINOv3, Siglip2) are lazy and belong
#     to pipelines this application never loads. WanVideoPipeline, ModelConfig,
#     wan_video_dit_s2v and Wav2Vec2 were all verified to import on 4.57.1.
#
# gradio is pinned to 5.x for the same reason, one dependency removed:
# transformers 4.57.1 requires huggingface-hub < 1.0, and gradio 6.x requires
# huggingface-hub >= 1.16. They cannot coexist. gradio 5.49.1 accepts hub 0.36.x.
# Raising gradio to 6.x therefore breaks VOICE, not the UI -- which is not where
# anyone would look for the failure.
#
# torchcodec is required from torch >= 2.9, which coqui-tts enforces at import
# time. It is installed WITHOUT the coqui-tts[codec] extra for the same reason
# the voice requirement takes no extras: the extra resolves through Coqui's cu128
# index. The plain wheel links against the installed torch and leaves it alone.
#
# FFMPEG SHARED LIBRARIES ARE A SYSTEM PREREQUISITE, not a pip dependency, and
# nothing in this file can install them. torchcodec links against the FFmpeg
# shared library set; imageio-ffmpeg (in requirements-core.txt) ships only an
# EXECUTABLE, which satisfies the muxing in export.py but not torchcodec. Without
# the libraries torchcodec cannot load its own core DLLs, and coqui-tts then
# refuses to import at all -- so the VOICE role fails at import time, with a
# ctypes traceback that names neither FFmpeg nor the fix.
#
#   winget install --id Gyan.FFmpeg.Shared      # then open a NEW shell
#
# Verified on the production host with FFmpeg 9.0.1 (torchcodec supports 4-9).
# PyAV is NOT a substitute despite bundling FFmpeg: delvewheel renames its
# libraries (avutil-60-cc1777....dll), so torchcodec cannot resolve them by the
# names it links against. Measured, not assumed -- it was tried and rejected.

# --- Voice: VOICE role (resolved 2026-09-01 against the T007 gate) ---
# XTTS-v2 through coqui-tts. Arabic is a hard requirement, which rules out
# CosyVoice2 (9 languages, no Arabic). The XTTS tokenizer carries Arabic
# abbreviation, symbol, ordinal and punctuation rules rather than inheriting
# Arabic incidentally from a multilingual checkpoint.
#
# NO EXTRAS. This requirement is deliberately written without [cuda] or [cpu].
# coqui-tts declares torch and torchaudio ONLY inside those optional extras, so
# a bare install touches neither, and the platform cu130 wheels installed in
# step 1 survive untouched. Adding an extra here would resolve torch from
# coqui-tts's own cu128 index and strip sm_120 support from the RTX 5080 -- the
# exact failure this file's header warns about, arriving through a dependency.
# Its floors are satisfied by what step 1 already installs: torch>=2.2 against
# 2.13.0+cu130, torchaudio>=2.2.0 against 2.11.0+cu130.
#
# transformers>=4.57 is a floor, not a pin, so it is satisfied by the 5.16.1
# pinned above for Wan's Wav2Vec2 encoder. The two halves of the stack do not
# contend for it.
#
# Rejected alternative: ResembleAI/chatterbox (23 languages, Arabic, MIT). The
# capability fits, but chatterbox-tts 0.1.7 hard-pins torch==2.6.0 in its
# upstream pyproject.toml, which is the GPU-disabling downgrade described above.
#
# LICENCE TRIPWIRE -- two separate obligations, do not conflate them:
#   * the coqui-tts PACKAGE is MPL-2.0, and imposes nothing here;
#   * the coqui/XTTS-v2 WEIGHTS are CPML, which forbids COMMERCIAL use.
# This project is non-commercial, so CPML is satisfied today. If that ever
# changes, the voice model MUST be replaced before release -- Chatterbox in a
# separate virtualenv, invoked as a subprocess, is the recorded exit.
coqui-tts==0.27.5          # NO EXTRAS -- see above
torchcodec==0.16.0         # audio IO for torch >= 2.9; plain wheel, not [codec]
